## Isolation and cleanup

The harness used a new git worktree, a separate OS home, a separate `MS_HOME`,
private Claude settings/hooks, a private Codex configuration and rollout store,
an empty working directory, and a unique tmux socket. No existing user pane was
controlled or respawned. Real usage availability was checked with bounded,
read-only requests; expired credentials were not refreshed by the harness.

Claude inference tokens and still-valid Codex access material were copied only
into private files. Original refresh grants were never copied: the private Codex
credentials explicitly disabled refresh. No original settings, shared session
store, or real managed-session database was linked into the disposable homes.
Credentials and raw child output were excluded from the report and command logs.

Before authorizing the release runner's real-store upgrade/refresh, a private
integrity comparison confirmed that every source credential file used by the
harness remained unchanged. The comparisons were not printed. Subsequent
release-runner updates to those originals are outside that checkpoint.

Cleanup verified that the owned tmux server was gone and that zero processes
held files in the private tree, then deleted the private tree and all copied
credential material. The private, untracked harness is not part of the release.

## Probe setup corrections and remaining coverage

An initial Codex probe used an unavailable older model name; rerunning with the
currently advertised `gpt-6.1-sol` succeeded. An initial scratch path used the
macOS `/tmp` alias, which disagreed with Codex's canonical hook-trust path; the
scratch environment was recreated using canonical paths and all Codex hooks
then fired. These were harness setup corrections, not application fixes.

The first nested Claude attempt lacked an inference token in its tool subprocess.
The retest read only the private copied credential into the child's environment;
both nested children then succeeded without changing the parent's identity.

This run does not establish live credential refresh, a deliberately exhausted
fleet, sleep/wake timing, a distinct live model change, or Codex-parent nesting.
It did observe a genuine pre-existing Claude wall and the corresponding waiting
behavior. Broader deterministic tests and the final release artifact checks
remain separate evidence and should be reported as such.
