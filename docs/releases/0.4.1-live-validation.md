## Failures found and retested

The scanner originally let `app-server` and daemon helpers claim a frontend's
rollout. The import parser also treated the supported Boolean `--no-daemon` as
an unknown value-taking option. Both defects reproduced before the fix; the
corrected scanner planned one real frontend and no helper rows. Forced cleanup
now protects service subtrees, and old manifests naming a daemon cannot signal it.

A daemon-backed import also exposed the importer's 60-second deadline racing the
launcher's existing 75-second writer wait. Its deadline now includes both waits.
Current Codex 0.163.0 retains unsubscribed threads for 1,800 seconds by default;
normal UI Ctrl-C exit still left the private daemon's writer held after 31 seconds.
It has no supported operation for a new client to unload another client's thread.
The importer therefore refuses a live source whose writer is demonstrably held by
a background service. Start plain `codex --no-daemon` for the supported live-import
path, or close and wait for release before adopting. No daemon was stopped to make
an import pass.

The first in-process import retest exposed a harness error: a newly created login
shell reset PATH and selected Homebrew Codex 0.157.0. That move succeeded but was
not counted as the latest-target proof. The corrected owned no-profile shell and
private-prefix PATH produced the separately verified 0.163.0-to-0.163.0 result.
A Codex-parent read-only sandbox could not complete child inference; the successful
nested retest used its normal one-command approval dialog, without a persistent
approval or bypass mode.

Deterministic manual/recovery/rebalance/owner tests passed 231/231. The final
import scan/plan/execute/verb tests passed 110/110, including the reproduced bugs,
pre-signal refusal, unknown-owner fallback, and protected cleanup. Final integrated
source typecheck and build passed. The release runner owns the combined full
suite, CI, and installed artifact checks.

## Isolation checkpoint and remaining coverage

The harness used a new worktree, private exact CLI installs, its own OS home,
`MS_HOME`, canonical configuration paths, private hooks, rollout and lock stores,
and two uniquely owned tmux sockets. Existing user panes and settings were not
controlled or modified. Inference credentials were copied only into private files;
original refresh grants were never copied or refreshed. Child output was retained
only privately or summarized as exit/sentinel checks. Credentials, account paths,
and raw user conversation content are absent from this report.

All eight disposable managed sessions stopped with exit 0; all eleven private-store
rows, including the three synthetic stale rows, read stopped. Both owned tmux
servers were confirmed gone. A private integrity comparison after the final stop
confirmed every original credential file used by the harness was unchanged;
comparisons and file details were not printed. Remaining processes belonging only
to the private test environment were terminated after its clients closed. Zero
processes held the private tree before it and every copied credential were removed.
The harness and raw output were not committed.

Live credential refresh, deliberately exhausted fleets, sleep/wake timing, and
real automatic quota exhaustion were not exercised. Their bounded failure paths
remain deterministic-test coverage. Claude polling availability was intentionally
unavailable in the private store. Default-daemon live import remains the explicit
safe limitation described above.
